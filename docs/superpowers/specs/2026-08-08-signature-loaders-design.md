# Signature loaders

**Date:** 2026-08-08
**Status:** design agreed, not implemented
**Affects:** `nilam.components.css`, `nilam.motion.css`, `nilam.scale.css`, `nilam.tokens.css`, `build.mjs`, `src/css.mjs`

## The problem

The five loaders shipped in 0.6.1 are correct and anonymous. The contrast work is real
and the reduced-motion handling is better than most libraries ship, but a one-arc border
ring is the same spinner as Bootstrap, Tailwind UI, Chakra and MUI. Recolour it and
nobody could name the system it came from.

Nothing here is a bug fix. This is a deliberate change of appearance and behaviour.

## The two rules

Everything below is generated by these. If a proposed detail does not follow from one of
them, it does not ship.

**Rule 1 — the clock.** Every loader moves on a **100ms tick** and completes a cycle in
**twelve ticks (1.2s)**. 100ms is Miller's instantaneity limit — the interval below which
people stop perceiving discrete events as separate ([Miller
1968](https://dl.acm.org/doi/10.1145/1476589.1476628),
[Nielsen](https://www.nngroup.com/articles/response-times-3-important-limits/)). Twelve is
the scale. This is why five different shapes read as siblings.

**Rule 2 — the ramp.** Colour comes from the twelve solved brand steps, ordered by
**measured contrast against the page, strongest first**. The trail fade is not an opacity
trick; it is the palette being genuinely quiet at the tail.

Stepping is not part of the clock. `steps(12)` applies where one tick moves a small arc
(the ring). It does not apply to anything that travels a distance — twelve large position
jumps judder. Those share the 1.2s duration and slide smoothly.

## New tokens

### Motion, in `nilam.scale.css`

```css
--dur-tick:  100ms;   /* Miller's instantaneity limit */
--dur-cycle: 1.2s;    /* twelve ticks */
```

Two tokens rather than a magic number repeated six times.

### The loader ramp, generated into `nilam.tokens.css`

`--loader-1` … `--loader-12`, where `--loader-N` is the brand step with the Nth-highest
measured contrast against the page. Emitted per mode with `light-dark()`, exactly like
every other token, by `toCss()` in `src/css.mjs`.

**These must be computed, not written by hand.** The README promises the system re-derives
from one number, the hue. Change the hue and the contrast order can change; a hand-written
order silently becomes a lie while every assertion still passes. `build.mjs` already
imports `contrast()` from `src/colour.mjs` — the ordering is a sort over values it holds.

The order is expected to come out near `12, 11, 10, 8, 9, 7, 6, 5, 4, 3, 2, 1` in light
and `12, 10, 9, 11, 8, 7, 6, 5, 4, 3, 2, 1` in dark. **That is an estimate made by sorting
OKLCH lightness, which is not the premise the build will use** — WCAG contrast runs on
relative luminance, and chroma moves luminance. The build's output is the answer. If it
disagrees with the estimate, the estimate was wrong. Do not "correct" the build to match
this paragraph.

## Per-component changes

Class names, element choices and jobs are unchanged, so **no markup changes**. CSS
overrides can still break — see Breaking changes.

| Class | Change |
|---|---|
| `.n-spinner` | Twelve-sector conic ring, contrast-ordered, `steps(12)`. Cycle 0.6s → 1.2s, so it visibly slows |
| `.n-spinner-xl` | **New size**, 4rem, plus a counter-rotating depth layer at 3.6s (three cycles). The design was reviewed at 104px; 4rem is the shipped default and authors can size it up |
| `.n-bar` | Travelling block becomes the ramp as a gradient; slide is smooth, 1.4s → 1.2s |
| `.n-progress` | Fill becomes the ramp |
| `.n-dots` | Three ramp points; stagger 150ms → 100ms, cycle 1.2s |
| `.n-skeleton` | Cycle 1.4s → 1.2s. **Keeps steps 5/7** — that pairing is a solved defect fix, not decoration |
| `.n-btn[aria-busy]` | Same ring construction, ink-derived |

### Construction of the ring

The element carries the mask and stays still. A `::before` carries the gradient and
rotates. This keeps the wake and persist animations on the element independent of the
rotation, and lets `.n-spinner-xl` add a second counter-rotating `::after` without the two
layers compounding.

```css
.n-spinner { position: relative; border-radius: var(--r-full);
             mask: radial-gradient(closest-side, #0000 62%, #000 64%); }
.n-spinner::before { position: absolute; inset: 0;
             background: conic-gradient(from 0deg, var(--loader-1) 0 30deg, /* … */);
             animation: n-spin var(--dur-cycle) steps(12) infinite; }
```

`border` and `border-width` come off `.n-spinner` and `.n-spinner-sm`. Rotate the element
via transform only — animating gradient stops is the paint-expensive mistake
([nerdy.dev](https://nerdy.dev/android-spinner-conic-gradient-animation)).

Softness on `.n-spinner-xl` comes from mask gradients, never `filter: blur()`. Blur
re-renders every frame; masks ride the compositor.

## Time-awareness

Miller gave three thresholds. All three become visible, in CSS, with no JavaScript, no
timers and no state.

| Elapsed | State | Mechanism |
|---|---|---|
| 0 – 1.2s | Faint | `n-wake` runs once with `both` |
| 1.2s+ | Full contrast | `n-wake` has finished |
| 10s+ | Slow breath, message revealed | `animation-delay: 10s` on an infinite animation |

```css
@keyframes n-wake        { from { opacity: 0.3 } to { opacity: 1 } }
@keyframes n-persist     { 0%, 100% { opacity: 1 } 50% { opacity: 0.55 } }
@keyframes n-slow-reveal { 0%, 99.9% { visibility: hidden; opacity: 0 }
                           100%      { visibility: visible; opacity: 1 } }
```

`n-wake` animates opacity only — no scale. That is smaller code and it means the animation
is already reduced-motion-safe by construction, since opacity is exactly what the
exemption preserves.

The 10s message is an optional `.n-slow` element inside `.n-loading`. Authors who do not
add it get nothing extra; nothing breaks.

**Why a request finishing in 300ms is better off:** it shows a faint indicator that never
brightens, instead of a full-strength flash. This replaces the "delay the spinner by
N milliseconds" convention, which was considered and rejected — the field ranges from
100ms to 600ms with no derivable value, and inventing one would be the exact sin this
package exists to avoid.

## Reduced motion

Every new animation name must be added to the `prefers-reduced-motion` exemption in
`nilam.motion.css`, including the new `::before` and `::after` selectors.

This omission has frozen these loaders twice: once for three releases when the exemption
sat in the wrong layer, and again when `.n-skeleton` was missing from the selector list
and breathed exactly once. A hand-maintained list drifts.

**Test:** parse the built `nilam.css`, collect every animation name used by a loader
selector, and fail if any is absent from the reduced-motion block. The premise is the
built CSS, not a list a human keeps in step.

## Proof

Added to the existing `prove` run, so a failure aborts the build rather than emitting a
palette that lies:

1. `--loader-1` clears **3:1** against the page, against `--surface` (a card), and against
   every filled button background. It is the head of the trail and the one sector that
   must always be findable.
2. The twelve `--loader-N` are a permutation of the twelve brand steps — no value
   invented, none dropped, none repeated.
3. The ordering is strictly descending by measured contrast against the page.

Assertion 1 must measure against each surface separately. Measuring only against the page
is the closed loop that produced the 3.05:1-on-paper / 2.70:1-on-a-card defect already
recorded in this repository.

## Stated residuals

**The filled button has no ramp.** On `--brand-9` the brand ramp is invisible, so there is
no twelve-step sequence to draw from. That ring uses twelve stops of `--brand-ink` at
evenly-stepped alpha — stop *N* at `100 - (N-1) × 100/12` percent, so 100% down to
roughly 8%. Even spacing is a stated rule, not a solved value. This is the one place the
derivation does not reach, and it is recorded rather than dressed up.

**Twelve is not countable below about 28px.** At 18px each sector is roughly 3.8px of arc.
It renders and the rotation reads clearly, but you cannot count twelve. Countability was
never a requirement; `.n-spinner-xl` is where the palette gets room to perform. An earlier
draft proposed varying the sector count by size using "the largest divisor of twelve that
clears a pixel budget" — dropped, because the budget constant would have been invented.

**Unverified: the 10s announcement.** `visibility: hidden → visible` should remove the
message from the accessibility tree and then trigger a polite announcement inside
`role="status"`. That is a belief about live-region behaviour, not a tested fact. It ships
as a task with a real screen-reader check. If it does not announce, the visual reveal
still stands on its own and the claim comes out of the docs.

## Out of scope

- WebGL or canvas loaders. Considered and rejected: a GPU context per instance, colours
  duplicated in JS away from the token system, and the loss of the one-`@import` promise.
- Any new component. `.n-spinner-xl` is a size modifier on an existing class.
- A JS behaviour module. These are CSS-only.

## Breaking changes

Minor bump — **0.7.0**.

- `.n-spinner` and `.n-spinner-sm` no longer use `border`. Anyone overriding
  `border-color` on a spinner loses that override.
- `.n-spinner-on-fill` is rewritten; it sets gradient stops rather than border colours.
- `.n-spinner` gains a `::before`. Anyone who styled that pseudo-element is affected.

## Success criteria

1. `node build.mjs` emits `--loader-1` … `--loader-12` for both modes and all assertions pass.
2. Changing the hue (`node build.mjs 262`) re-derives the order; the emitted CSS changes
   and assertions still pass.
3. The reduced-motion test fails when an animation name is deliberately removed from the
   exemption, and passes when it is restored.
4. Visual-regression baselines updated for all five loaders in both modes.
5. A real screen reader is used on the 10s reveal, and the result — either way — is
   written into the docs.
